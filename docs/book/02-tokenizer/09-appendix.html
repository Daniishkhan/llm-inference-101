Reading a traceback

Module 1's appendix took a traceback apart (Reading a traceback): the calls in progress when the exception was raised, oldest first, read from the bottom up. This module adds three things: the message of a KeyError, tracebacks that pass through a test into your package, and an exception turned into another.

A lookup that fails three calls down

A small program in the shape of this module's code: it reads a JSON file into a dict, then looks names up in it, one function calling the next. The last name is not in the dict:

import json
import tempfile
from pathlib import Path


def load_codes(path):
    return json.loads(path.read_text(encoding="utf-8"))


def code_of(codes, station):
    return codes[station]


def route_codes(codes, route):
    return [code_of(codes, station) for station in route]

Trap

Read a KeyError's key character by character. In this module the classic is a key with or without its space, or with a space where the file has Ġ: KeyError: ' world' says you looked up the token's bytes as text, while vocab.json writes that token as "Ġworld" (chapter 4). The quotes in the message are repr's, so a leading space shows as ' world' and a newline as '\n'.

The "still running after 2 s" messages, and the training test's "still training after 10 s", come from an alarm. A test asks the operating system to send the process a signal, SIGALRM, after two seconds (ten for training), and installs a handler that raises an exception when it arrives; Python runs the handler between two bytecode instructions of whatever your code is doing, and the test catches the exception and fails with its message. In a finally, it switches the alarm off and puts the old handler back, so a fast answer is never interrupted. The same mechanism, on a loop that never ends:

import signal


class StillRunning(Exception):
    pass


def ring(signum, frame):
    raise StillRunning


def count_for_ever():
    total = 0
    while True:
        total += 1


before = signal.signal(signal.SIGALRM, ring)
signal.setitimer(signal.ITIMER_REAL, 0.2)
try:
    count_for_ever()
except StillRunning:
    print("still running after 0.2 s: the alarm rang, and a test would fail here")
finally:
    signal.setitimer(signal.ITIMER_REAL, 0)
    signal.signal(signal.SIGALRM, before)
print("the alarm is off and the old handler is back")

still running after 0.2 s: the alarm rang, and a test would fail here
the alarm is off and the old handler is back

Python runs the handler only between instructions of Python code, so a long call into C or Rust is interrupted only when it returns.

Glossary

Alarm
A signal (SIGALRM) that the operating system sends a process after a set time; the tests use one to stop a function that takes too long (9).
BPE (byte-pair encoding)
Learning a tokenizer by merging the most frequent pair of neighbouring tokens into a new token, again and again; encoding replays the merges (2).
Byte
Eight bits: a number from 0 to 255. Files, sockets and this module's tokenizer see bytes, not characters (1).
Byte-to-character map
GPT-2's table from each of the 256 bytes to one printable character, so that tokens can be written in text files; it is why space is Ġ (4).
Characters per token
A text's length in characters divided by its tokens: about 4.5 for plain English prose with GPT-2, below 1 for some scripts (6).
Chunk
One piece of text after the split, such as " world"; merges never cross from one chunk to the next (3).
Code point
The number Unicode gives a character, from 0 to 0x10FFFF, written U+00E9; ord gives it (1).
Context window
The most tokens a model can hold at once, prompt and reply together: 1,024 for GPT-2 (6).
Continuation byte
A byte of the form 10xxxxxx: the second, third or fourth byte of a character in UTF-8 (1).
Decode (model)
The phase in which a model writes its reply, one token per step (6).
Decode (tokenizer)
Turning ids back into text: join the tokens' bytes, then decode them as UTF-8 (3).
Embedding table
The table inside a model with one row of numbers per token of the vocabulary; a token's row is looked up by its id (6).
Heap
A list kept in an order where each item is no larger than its two children, so the smallest is always at position 0; push and pop cost log n (5).
Linked list
Items that each hold a link to the next (and perhaps the previous), so that one can be removed or joined without moving the rest (5, 7).
Merge
One learned rule of BPE: this pair of tokens, side by side, becomes this new token (2).
Node
One link of a linked list: a value and a reference to the next node, or None at the end (7).
Oracle
A trusted implementation the tests compare yours with: tiktoken, built from the same two files (4).
Pre-tokenization (the split)
Cutting text into chunks with a regular expression before any merge, so that words, numbers, punctuation and spaces are merged separately (3).
Prefill
The phase in which a model reads the whole prompt in one go, in parallel, ending with the first token of the reply (6).
Rank
A merge's place in the order of learning: merge r has rank r, makes token 256 + r, and lower ranks are applied first (3).
Replacement character
U+FFFD, �: what errors="replace" puts in place of each broken piece of UTF-8 (1, 3).
Round trip
Doing something and then its inverse and getting back what you started with: decode(encode(text)) == text (3).
Shift and mask
>> and << move bits; & keeps the bits you choose. Together they take a number apart into fields (1).
Softmax
Turning a model's scores, one per token of the vocabulary, into probabilities that add up to 1 (6; Module 3).
Special token
A token that no merge makes and that ordinary text never produces, such as GPT-2's <|endoftext|>, id 50,256 (4).
Stale entry
An item left in a heap after the thing it described has changed; it is recognised and skipped when it reaches the top (5).
Surrogate
A code point from U+D800 to U+DFFF, half of a UTF-16 pair. Not a character; UTF-8 has no bytes for it (1).
Token
One unit of a tokenizer's vocabulary: a run of bytes, often a word with its leading space (2).
Token id
A token's number, from 0 to 50,256 for GPT-2; what a model reads and writes (2).
Unicode property
A class of characters by meaning, such as \p{L} (letters) or \p{N} (numbers), in the regex package (3).
UTF-8
The encoding that writes each code point as one to four bytes, with ASCII as single bytes (1).
Vocabulary
Every token a tokenizer knows: for GPT-2, 256 bytes, 50,000 merges and one special token, 50,257 in all (2, 6).

What Module 3 brings

Module 3 is the forward pass: GPT-2 small written in numpy, loaded from its safetensors file (a simple file format for a model's arrays of numbers), and run with greedy generation, always taking the most likely next token. A preview, so that you recognise the names; nothing here is needed this module.

  • Your token ids are its input. The ids your load_gpt2() makes are exactly the numbers GPT-2 small was trained on, so Module 3 starts where this module ends.
  • Embeddings are a lookup by id. The first thing the model does with an id is read row id of its embedding table, 768 numbers for GPT-2 small. No arithmetic, just indexing.
  • Then the layers: attention, which lets each token look at the tokens before it, and an MLP, twelve times over, each layer changing the rows a little.
  • Then the logits: one score for each of the 50,257 tokens, and the softmax, written so that it does not overflow.
  • Done when its logits match a reference implementation's within tolerance on 20 prompts.

An embedding table is an array with one row per token, and numpy reads several rows at once when you index it with a list of ids. A toy vocabulary of six tokens, four numbers each:

Check yourself

A test fails, and its traceback has entries in tests/m02/test_gpt2.py, then src/llm101/tokenizer/gpt2.py, then src/llm101/tokenizer/bpe.py, ending in KeyError: (32, 116). Where do you look first, and what is the key?

Answer

The lowest entry, in bpe.py: a dict was read with the key (32, 116), a pair of ids, and it does not have it. Then walk up into gpt2.py to see how that dict was built and what it was given.

What does UnicodeDecodeError: ... unexpected end of data tell you about the bytes, and what does errors="replace" make of them?

Answer

The bytes stop partway through a character: a start byte promised more bytes than there are. With errors="replace" the broken piece becomes one �.

Why does Path("data/gpt2/vocab.json") work from the repository's root and fail from scratch/, and what does not?

Answer

A relative path is looked up from the folder the program runs in. VOCAB_PATH is built from the location of gpt2.py, so it is absolute and works from anywhere.

A file of 50,001 lines ends with a newline. How many pieces does text.split("\n") give, and what goes wrong if every piece is unpacked into two names?

Answer

50,002: one per line and an empty one after the last newline. The empty piece splits into no words, so unpacking it raises ValueError: not enough values to unpack (expected 2, got 0).

How does a test stop your function after two seconds, and why can it not stop a long call into C?

Answer

It sets an alarm (signal.setitimer) whose handler raises an exception; Python runs the handler between bytecode instructions, so the exception appears inside your loop. A call into C or Rust runs no bytecode until it returns, so the handler waits until then.

Hypothesis reports text='\x85'. What is it, and how do you find out?

Answer

U+0085, a control character called "next line": invisible, two bytes in UTF-8, and one of the characters that str.splitlines() treats as a line break. Paste it into a scratch program and print f"U+{ord(c):04X}" and c.encode("utf-8").

Why does re.findall(r"\p{L}+", text) raise, and what do you change?

Answer

The standard library's re does not know Unicode properties, so \p is a bad escape. Use the regex package: regex.findall(r"\p{L}+", text).
