The problem: a column of numbers says nothing

By milestone M4 your harness has a thousand wall times and their percentiles. Print the list and a thousand lines of digits scroll past; the three calls that took twenty times as long as the rest are in there, and you will not see them. Even p50, p95 and p99 do not show a shape: one hump, two, or a hump with a long thin tail?

People read pictures faster than columns. In a table with aligned columns the eye jumps to the number it wants; a bar chart turns "81.2, 54.0, 60.5, 0.4" into lengths, compared without reading. This chapter draws both with characters in the terminal, for a year of rainfall at a hill weather station. M5 asks you to draw your benchmark's report the same way; you design it.

The library is rich, which is already a dependency of the project (uv sync installed it). It draws tables, colours, bars and live displays in a terminal.

First principle

A terminal shows only characters, in a grid of fixed-width cells, one row after another. Everything "graphical" in it is characters chosen carefully: a table's borders are the box-drawing characters ┏ ━ ┃ │, a bar is a run of ▇ or #, and colour and bold are invisible control sequences that the terminal interprets. rich's job is to turn your objects into the right characters for the width of the window, and to leave out the control sequences when the output is not going to a terminal at all.

Console and print

rich's centre is the Console: an object that knows where the output goes (the screen, unless you say otherwise), how wide it is, and whether it can show colour. Its print method looks like the built-in one, and does more:

from rich.console import Console

console = Console()
print("Rain today: [bold]12 mm[/bold]")
console.print("Rain today: [bold]12 mm[/bold]")
console.print("Wind:", 24, "km/h")

Rain today: [bold]12 mm[/bold]
Rain today: 12 mm
Wind: 24 km/h

The built-in print prints the string exactly as written, square brackets and all. console.print reads [bold] and [/bold] as instructions: in your terminal, "12 mm" appears in bold, and the tags themselves are not printed. (The output above shows no bold, because this book shows plain text; when rich sees that it is writing to a file or a pipe rather than a terminal, it leaves out the styling.) Like the built-in, console.print takes several arguments and puts a space between them.

Markup

The square-bracket tags are rich's markup, a small language modelled on HTML. A tag opens a style, a tag with a slash closes it, and several styles can share one tag:

from rich.console import Console

console = Console()
console.print("[bold]bold[/bold], [italic]italic[/italic], [underline]underlined[/underline]")
console.print("[blue]blue[/blue] and [bold red]bold red[/bold red] and [dim]dim[/dim]")
console.print("[green]a tag stays open until it is closed, [/green]then it ends")
console.print("[bold]bold up to here[/], plain after a bare closing tag")

bold, italic, underlined
blue and bold red and dim
a tag stays open until it is closed, then it ends
bold up to here, plain after a bare closing tag

Run it in your own terminal to see the styles. A style name can be a weight (bold, dim), a slant (italic), underline, or a colour (red, blue, green...). A bare [/] closes the most recent tag. Markup is convenient for text you write yourself. It becomes a hazard for text you did not write, such as a line of source code, which is the trap later in this chapter.

Analogy

Markup is a typesetter's pencil marks on a manuscript: "bold from here... to here". The typesetter follows the marks and does not print them. Where it breaks: a typesetter can tell a pencil mark from the author's own brackets by looking. rich cannot: anything in the text that looks like a tag is taken as one, which is exactly how it eats a Python list.

Text: styled text as an object

Markup lives inside a string. rich's Text class is the other way to style: an object that holds plain characters and, separately, which ranges have which style. You build it in pieces with append, each piece with its own style, and it never reads square brackets as tags:

from rich.console import Console
from rich.text import Text

console = Console()
line = Text("Rain: ")
line.append("12.4 mm", style="bold blue")
line.append(" (wettest day [so far])")
console.print(line)
print(len(line), "characters;", repr(line.plain))

Rain: 12.4 mm (wettest day [so far])
36 characters; 'Rain: 12.4 mm (wettest day [so far])'

The brackets in "[so far]" came through untouched, because a Text holds characters, not markup. len counts its characters, and .plain gives them back as an ordinary string, without styles. Use markup for quick labels you type, and Text when a program assembles the text from pieces, especially pieces from outside.

Table: rows and columns

A Table is built in two steps: declare the columns, then add rows. rich works out each column's width from the widest thing in it, draws the borders, and aligns the cells:

from rich.console import Console
from rich.table import Table

months = ["Jan", "Feb", "Mar", "Apr", "May", "Jun"]
rain_mm = [81.2, 54.0, 60.5, 0.4, 47.9, 0.0]
rain_days = [16, 12, 13, 1, 10, 0]

table = Table(title="Rainfall, first half of the year")
table.add_column("Month")
table.add_column("Rain (mm)", justify="right")
table.add_column("Wet days", justify="right")
for month, mm, days in zip(months, rain_mm, rain_days):
    table.add_row(month, f"{mm:.1f}", str(days))

Console(width=60).print(table)

Group: several things printed as one

A report is usually more than one table: a heading, a table, a sentence. Group, from rich.console, holds several printable things and prints them one under the other, as if they were one:

from rich.console import Console, Group
from rich.table import Table
from rich.text import Text

table = Table()
table.add_column("Day")
table.add_column("Rain (mm)", justify="right")
table.add_row("Mon", "4.2")
table.add_row("Tue", "0.0")

forecast = Group(Text("Rain this week", style="bold"), table, Text("Dry from Tuesday."))
Console(width=40).print(forecast)
print(type(forecast).__name__, len(forecast.renderables), "pieces")

Anything that rich can print is called a renderable: a string, a Text, a Table, a Group of any of those. The type that covers them all is rich.console.RenderableType, which you will meet in the signature of render_report.

Reading what rich printed

How does a test check a table? It cannot look at your screen. rich solves this with two options of the console. file=io.StringIO() sends the output into a string in memory instead of to the screen; io.StringIO is a "file" that lives in memory. record=True makes the console keep a copy of everything it printed, and export_text() hands that copy back as plain text, without styles:

import io

from rich.console import Console
from rich.table import Table

table = Table()
table.add_column("Month")
table.add_column("Rain (mm)", justify="right")
table.add_row("Jan", "81.2")
table.add_row("Feb", "54.0")

console = Console(file=io.StringIO(), record=True, width=40)
console.print("[bold]Rainfall[/bold]")
console.print(table)
text = console.export_text()

print("nothing reached the screen until this line")
print(repr(text.splitlines()[0]))
print(len(text.splitlines()), "lines")
print("81.2" in text, "[bold]" in text)
print(text, end="")

This is exactly how the M5 tests read your report: they make a console like this one, with color_system=None as well, print what render_report returned, take export_text(), and search the text for "p99" and for the bars. Bars that mean something

A bar chart turns each number into a length. The rule that makes it honest is proportion: a bar twice as long means a value twice as large. Choose a full width, say 30 characters, for the largest value; every other bar is then its value divided by the largest, times 30, rounded to a whole number of characters with round(). One exception: a value that is not zero but rounds to zero characters would vanish and look the same as a true zero, so give it one character. Here is the rule on six months of rain, with ▇ as the bar:

from rich.console import Console
from rich.text import Text


def rain_bars(months: list[str], rain_mm: list[float], width: int) -> Text:
    """A bar per month, the wettest month `width` characters long. Returned, not printed."""
    wettest = max(rain_mm)
    chart = Text()
    for month, mm in zip(months, rain_mm):
        length = round(mm / wettest * width)
        if mm > 0 and length == 0:
            length = 1  # a little rain still gets a mark
        chart.append(f"{month} {mm:5.1f} ")
        chart.append("▇" * length, style="blue")
        chart.append("\n")
    return chart


months = ["Jan", "Feb", "Mar", "Apr", "May", "Jun"]
rain_mm = [81.2, 54.0, 60.5, 0.4, 47.9, 0.0]
Console().print(rain_bars(months, rain_mm, width=30), end="")

Check one bar: March is 60.5 / 81.2 × 30 = 22.35, which round() makes 22. April's 0.4 mm gives 0.15, which rounds to 0, and the rule lifts it to 1, so a little rain looks different from June's none.

Python you need

round(x) rounds to the nearest whole number and returns an int. When x is exactly half way, it rounds to the even neighbour: round(2.5) is 2 and round(3.5) is 4 (this is called banker's rounding). int(x) is different: it chops off the fraction, so int(22.9) is 22. For bar lengths that should match someone else's rule, use the same function they did.

Notice that rain_bars prints nothing. It returns a Text, and the caller decides where it goes: the screen, as here, or a recording console, as in a test. A function that prints can only be tested by capturing the screen; one that returns a renderable can be tested by calling it. render_report's docstring says the same: "Return it; do not print it."

A worked example: the weather report

Now the whole year: a table with each month's rain, its share of the year and a total, then the bar chart, all returned from one function as a Group. The program prints it to the screen, then into a recording console, as a test would, to check the bars at another width:

import io
import re

from rich.console import Console, Group, RenderableType
from rich.table import Table
from rich.text import Text

MONTHS = ["Jan", "Feb", "Mar", "Apr", "May", "Jun", "Jul", "Aug", "Sep", "Oct", "Nov", "Dec"]
RAIN_MM = [81.2, 54.0, 60.5, 0.4, 47.9, 0.0, 12.6, 33.1, 58.8, 92.7, 101.3, 88.4]


def rain_table(rain_mm: list[float]) -> Table:
    table = Table(title="Hill station, 2025")
    table.add_column("Month")
    table.add_column("Rain (mm)", justify="right")
    table.add_column("Share", justify="right")
    year = sum(rain_mm)
    for month, mm in zip(MONTHS, rain_mm):
        table.add_row(month, f"{mm:.1f}", f"{mm / year:.1%}")
    table.add_row("[bold]Year[/bold]", f"[bold]{year:,.1f}[/bold]", "100.0%")
    return table


def rain_chart(rain_mm: list[float], width: int) -> Text:
    wettest = max(rain_mm)
    chart = Text()
    for month, mm in zip(MONTHS, rain_mm):
        length = max(1, round(mm / wettest * width)) if mm > 0 else 0
        chart.append(f"{month} ")
        chart.append("#" * length, style="blue")
        chart.append(f" {mm:.1f}\n" if mm > 0 else "  dry\n")
    return chart


def weather_report(rain_mm: list[float], width: int = 30) -> RenderableType:
    """The table, then the chart, as one thing that rich can print."""
    return Group(rain_table(rain_mm), Text(""), rain_chart(rain_mm, width))


report = weather_report(RAIN_MM)

# The caller decides where it goes: here, the screen.
Console(width=60).print(report)

# And here, a string, which is how a test reads it.
console = Console(file=io.StringIO(), record=True, width=60)
console.print(weather_report(RAIN_MM, width=10))
text = console.export_text()
bars = [len(run) for run in re.findall("#+", text)]
print("bars at width 10:", bars)

Read it from the bottom up. weather_report asks rain_table and rain_chart for their pieces and returns them in a Group, with an empty Text as a blank line between. Each function does one thing and returns it, so each can be checked alone. Details:

  • f"{mm / year:.1%}" multiplies by 100 and adds the % sign: 81.2 / 630.9 is 0.1287, shown as 12.9%.
  • The total row uses markup, [bold]Year[/bold]: a table cell given as a string is read as markup, just like console.print.
  • The chart's length line is the same rule as rain_bars, written as one expression: max(1, round(...)) for a month with rain, 0 for a dry one, and the dry month says so in words.
  • The last three lines are a test in miniature: at width 10, November gets the full 10 characters, April still gets 1, and dry June gets no bar, so the list holds 11 bars for 12 months.

Numbers people can read

A table is only as readable as the numbers in it. 4965799096 is a number; 4,965,799,096 is a number you can read; 5.0 GB is one you can take in. Python's f-strings do the formatting through a small code after a colon inside the braces:

mm = 1234.5678
print(f"[{mm}]")
print(f"[{mm:.2f}]")       # two decimals
print(f"[{mm:,.1f}]")      # a comma every three digits, one decimal
print(f"[{mm:>12,.2f}]")   # right-justified in 12 characters
print(f"[{'Jan':<6}]")     # left-justified in 6
print(f"[{'Jan':>6}]")     # right-justified in 6
print(f"[{1_000_000:,}]")  # whole numbers too
print(f"[{0.1612:.1%}]")   # a share as a percentage

The parts combine in a fixed order: alignment and width first, then the comma, then the precision and the type, as in >12,.2f. The square brackets in the output are plain characters in those strings, there to show where the padding ends; the built-in print does not read markup.

Choosing a unit

Commas help, but a column of byte counts from 812 to nearly five billion is still hard to compare. The fix is to choose, for each value, the largest unit in which it is still at least 1, and show one decimal:

def readable_bytes(size: int) -> str:
    """A byte count in the largest unit that keeps the number at 1 or more."""
    for unit, scale in [("GB", 1_000_000_000), ("MB", 1_000_000), ("KB", 1_000)]:
        if size >= scale:
            return f"{size / scale:.1f} {unit}"
    return f"{size} B"


files = {
    "notes.txt": 812,
    "photo.jpg": 2_431_877,
    "song.mp3": 6_210_442,
    "model.safetensors": 4_965_799_096,
    "empty.log": 0,
}
for name, size in files.items():
    print(f"{name:<18} {size:>15,} B {readable_bytes(size):>9}")

notes.txt                      812 B     812 B
photo.jpg                2,431,877 B    2.4 MB
song.mp3                 6,210,442 B    6.2 MB
model.safetensors    4,965,799,096 B    5.0 GB
empty.log                        0 B       0 B

The list of units runs from the largest down, and the first one that fits wins; anything under a thousand stays in bytes. Here a kilobyte is 1,000 bytes, as disk makers count; operating systems often use 1,024 (and should call it a kibibyte, KiB). Whatever you choose, say it, and use the same rule in every row. Your M5 report has the same problem with times, from nanoseconds to seconds, and render_report's docstring leaves the rule to you.

Trap

A unit chosen per value can make a column harder to scan: "980.0 KB" sits above "1.1 MB", and the shorter-looking number is larger. When a column is for comparing, consider one unit for the whole column, chosen from its largest value.

The square-bracket trap

Here is the mistake that rich's markup sets up, and the one most likely to cost you an hour in M6. Print a line of Python source with console.print:

from rich.console import Console
from rich.markup import escape
from rich.text import Text

console = Console()
line = "squares = [i * i for i in range(3)]"
console.print(line)
console.print(escape(line))
console.print(Text(line))
console.print(line, markup=False)
print(repr(escape(line)))
console.print("[bold]x[/bold] and [1, 2, 3] and [red]y[/red]")

squares = 
squares = [i * i for i in range(3)]
squares = [i * i for i in range(3)]
squares = [i * i for i in range(3)]
'squares = \\[i * i for i in range(3)]'
x and [1, 2, 3] and y

The first line lost everything after "squares =". rich took [i * i for i in range(3)] for a tag (it starts with a lower-case letter and ends with a bracket), found no such style, and dropped it without an error. The next three lines are the three ways out:

  • rich.markup.escape(line) puts a backslash before each opening bracket that could start a tag (the repr shows it), and rich prints the backslashed bracket as a plain bracket.
  • Text(line) holds characters, not markup, so nothing in it is read as a tag. This works in a table cell too: give add_row a Text instead of a string.
  • markup=False turns markup off for that one call.

The last line shows rich's rule: [1, 2, 3] survived, because a tag must start with a lower-case letter, #, / or @. That is why the trap is easy to miss: a list of numbers prints fine, and the first index such as [i] or the first comprehension vanishes.

Trap

Any text you did not type yourself (a line of source code, a file name, a model's output, a user's input) can contain square brackets. Never pass it to rich as a markup string: wrap it in Text or escape it. The M6 test test_the_program_prints_the_slowest_lines_with_profile looks for the source line squares = [i * i for i in range(20_000)] in your program's output, and a plain console.print of that line prints "squares =" and nothing more.

Arguments on the command line: argparse

Your program will take options such as --n 2000 --bins 30. They arrive in sys.argv as a list of strings, and picking through it by hand means writing the error messages, defaults and help yourself. The standard library's argparse does all that. Here it is on a unit converter, where --km 5 prints miles:

import argparse

MILES_PER_KM = 0.621371


def convert(argv: list[str] | None = None) -> None:
    """Read the arguments (argv, or the command line when argv is None) and print the miles."""
    parser = argparse.ArgumentParser(description="Convert kilometres to miles.")
    parser.add_argument("--km", type=float, default=1.0, help="distance in km (default 1)")
    parser.add_argument("--places", type=int, default=2, help="decimal places (default 2)")
    args = parser.parse_args(argv)
    miles = args.km * MILES_PER_KM
    print(f"{args.km:g} km is {miles:.{args.places}f} miles")


if __name__ == "__main__":
    convert()

1 km is 0.62 miles

The parameter argv makes it testable. parse_args(None) reads the real command line; parse_args(["--km", "5"]) reads the list you give it. So a test can call convert(["--km", "5"]) without starting a process, and the program, run normally, calls convert():

import argparse

parser = argparse.ArgumentParser(description="Convert kilometres to miles.")
parser.add_argument("--km", type=float, default=1.0)
parser.add_argument("--places", type=int, default=2)

Running a package as a program

Python you need

Every module has a variable __name__. When Python runs a file as the program, it sets __name__ to the string "__main__"; when the file is imported, __name__ is the module's own name. So if __name__ == "__main__": means "only when this file is the program, not when someone imports it". That lets a test import km_to_miles and call convert without the converter running on import.

print(f"__name__ is {__name__!r}")

if __name__ == "__main__":
    print("run as a program")
else:
    print("imported by someone else")

__name__ is '__main__'
run as a program

Imported instead (python -c "import whoami", from the same folder), it prints __name__ is 'whoami' and imported by someone else.

Your program is not a file, though: it is python -m llm101.bench. The -m flag says "find this module the way import would, and run it as the program". When the name is a package (a folder with an __init__.py), Python runs the file __main__.py inside it. Here is a tiny package to see it:

weather/
    __init__.py      the package: runs first, on any import of weather
    __main__.py      what python -m weather runs as the program

"""A tiny package: python -m weather runs weather/__main__.py."""

RAIN_MM = {"Jan": 81.2, "Feb": 54.0, "Mar": 60.5}

from weather import RAIN_MM

print(f"__name__ is {__name__!r}")
if __name__ == "__main__":
    wettest = max(RAIN_MM, key=RAIN_MM.get)
    print(f"wettest month so far: {wettest}, {RAIN_MM[wettest]} mm")

From the folder that contains weather/:

$ python -m weather
__name__ is '__main__'
wettest month so far: Jan, 81.2 mm
$ python weather/__main__.py
Traceback (most recent call last):
  File ".../weather/__main__.py", line 1, in <module>
    from weather import RAIN_MM
ModuleNotFoundError: No module named 'weather'

With -m, Python imports the package first (so __init__.py runs and the import works), then runs __main__.py with __name__ set to "__main__". Run as a plain file, Python looks for imports in the file's own folder, weather/, and among the installed packages, and finds no weather in either. That is why the course says uv run python -m llm101.bench: uv sync installed llm101 as a package, so -m finds it anywhere in the repository. The given src/llm101/bench/__main__.py already ends with if __name__ == "__main__":; what main does is M5.

A first look at rich.live

Everything so far prints once. Later modules draw pictures that change while the program runs: Module 9's batch slots, Module 10's map of memory blocks. rich's Live redraws a renderable in place instead of printing new lines. A rain-water tank filling:

import time

from rich.live import Live
from rich.text import Text


def tank(litres: int, capacity: int) -> Text:
    """A rain-water tank as one line: filled cells, empty cells and the level."""
    filled = round(litres / capacity * 20)
    line = Text("tank ")
    line.append("▇" * filled, style="blue")
    line.append("·" * (20 - filled), style="dim")
    line.append(f" {litres:>3} of {capacity} litres")
    return line


with Live(tank(0, 200), refresh_per_second=10) as live:
    for litres in range(0, 201, 20):
        live.update(tank(litres, 200))
        time.sleep(0.1)

tank ▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇ 200 of 200 litres

Inside with Live(...) as live:, each live.update(...) replaces what is shown, and in your terminal one line grows for a second. In this book, and in any output that is not a terminal, only the last picture is printed, because a file cannot be redrawn. Module 9 comes back to it.

Check yourself

What does Console().print("[bold]Total[/bold]: 12") show, and what does the built-in print show for the same string?

Answer

rich shows Total: 12, with "Total" in bold in a terminal; the tags are read as markup and not printed. The built-in print shows the string exactly as written, tags included.

The largest value in a chart is 40, the bar width is 20. How long are the bars for 30, 9, 1 and 0?

Answer

30 / 40 × 20 = 15. 9 / 40 × 20 = 4.5, and round(4.5) is 4 (half way goes to the even number). 1 / 40 × 20 = 0.5, which rounds to 0, so the at-least-one rule makes it 1. 0 gets no bar.

Why should a function that draws a table return it instead of printing it?

Answer

So that the caller decides where it goes. A program prints it to the screen; a test prints it into Console(file=io.StringIO(), record=True) and reads export_text(), with no screen involved. A function that prints can only be tested by capturing the screen.

Predict the output of f"[{2_431_877:>12,}]" and of f"{0.0042:.1%}".

Answer

[ 2,431,877]: the number with commas is 9 characters, right-justified in 12, so 3 spaces in front. And 0.4%: 0.0042 times 100 is 0.42, shown to one decimal.

A table cell is given the string "values[i]" and shows values. What happened, and give two ways to fix it.

Answer

A string in a table cell is read as markup, and [i] looks like a tag (it starts with a lower-case letter), so rich dropped it. Pass Text("values[i]") instead, or escape("values[i]") from rich.markup.

Why does python -m weather work where python weather/__main__.py fails on from weather import RAIN_MM?

Answer

-m finds weather as a package from the current folder, imports it, then runs its __main__.py as the program. Run as a plain file, Python looks for imports in the file's own folder, weather/, and among the installed packages, and neither holds a package called weather.

With the converter's parser, what is parser.parse_args(["--places", "0"]), and what does the program print for it?

Answer

Namespace(km=1.0, places=0): --km takes its default. It prints 1 km is 1 miles, because .0f rounds 0.621371 to 1 with no decimals.
